# Форматы файлов Hot Wheels: Beat That! (PC)

[English version](FORMATS.md)

Все числа little-endian, если не указано иное. Устройство архива и банков изучено по
[Technyx](https://github.com/PredatorCZ/Technyx) от Lukas Cone (PredatorCZ), остальное проверено на файлах
PC-версии. Все описанные ниже форматы проходят цикл «распаковка → пересборка» байт-в-байт.

## CDFILES.DAT (`filC`, версия 5) — индекс архива

| Смещение | Тип          | Поле                                               |
|---------:|--------------|----------------------------------------------------|
| 0x00     | char[4]      | `filC` (C = PC; P = PS2, X = Xbox, E = X360, N = Wii) |
| 0x04     | u32          | версия = 5                                          |
| 0x08     | u32          | 0x40000000 (float 2.0, версия кода)                |
| 0x0C     | u32[11]      | unk2, unk4, rootPathSize, unk3, numSearchPaths, workingPathSize, **numTotalFiles**, archivePathLength, **alignment (2048)**, **numFiles**, unkSize |
| …        | u32[numSearchPaths] | смещения путей поиска (здесь 0)             |
| …        | u32[2]       | 0                                                  |
| …        | char[workingPathSize] |                                           |
| 0x40     | char[16]     | `\ARCHIVE0.AR`                                     |
| 0x50     | u32[numTotalFiles] | смещение данных **в блоках по 2048 байт**     |
| …        | u32[numTotalFiles] | размер данных в байтах                       |
| …        | u32[numFiles] | смещение имени в дереве имён                     |
| …        | u32[numFiles] | id: биты 0–27 = индекс данных, 28–31 = тип (4 = StreamFile) |
| …        | u32[numFiles] | доп. данные                                       |
| …        | u32 n, u32 size, u32[n] offsets, char[size] | таблица фрагментов имён |
| …        | u32 + 128 байт | резерв                                           |
| …        | дерево имён  | каждое имя — последовательность индексов фрагментов (1 байт, или 2 байта big-endian при старшем бите), завершается 0; индексы с 1 |

В игре 2141 файл, имена плоские, без папок. Два имени повторяются (`DEFAULT_STANDARD2D.FX/.FXC`); при распаковке
второй экземпляр получает имя `ИМЯ~1.EXT`.

## ARCHIVE0.AR — данные

Файлы лежат друг за другом и выравниваются на 2048 байт. Промежутки заполнены **пробелами (0x20)**.
Ни сжатия, ни шифрования нет. `Data\` содержит версию высокой детализации, `lData\` — низкой: имена файлов те же,
но текстуры в `.ARC` меньше.

## .ARC — arcbank (`ARCC`)

| Смещение | Тип     | Поле                                      |
|---------:|---------|-------------------------------------------|
| 0x00     | char[4] | `ARCC`                                    |
| 0x04     | u32     | число записей (младшие 24 бита)           |
| 0x08     | u16[…]  | счётчики (текстуры, модели, …)            |
| 0x80     | entry[n]| записи по 16 байт                          |
| 0x80+16n | …       | данные; смещения в записях считаются от этой точки |

Запись: `u32 id/hash, u32 offset, i32 nameOffset (-1 = без имени), u8 type, u8[3] size (big-endian)`.
Данные идут по порядку, с выравниванием на 16 байт и заполнением нулями. **Одна запись — не больше 16 МБ**:
поле размера занимает 24 бита.

Типы записей: 0x00 PlainData, 0x01 Texture, 0x02 Material, 0x09 Mesh, 0x0F IndexBuffer, 0x10 VertexBuffer,
0x1C Attachment, 0x1D Model, 0x1E DeformedModel, 0x21 Skeleton, 0x29 Animation, 0xFD EntryNames (строки имён),
0xFF Group.

### Текстура

```
u32 width, height, numMips, hash, format
mip0, mip1, ...   // как в D3D9 / DDS
```
`format` — это значение D3DFORMAT: 21 = A8R8G8B8, 25 = A1R5G5B5, 26 = A4R4G4B4, 41 = P8 (палитра) или FourCC
`DXT1`/`DXT3`/`DXT5`. В игре: A4R4G4B4 — 7661, DXT3 — 2414, DXT1 — 435, A8R8G8B8 — 23, A1R5G5B5 — 1.
Имена текстур — это исходные имена файлов художников (`image001.tga`, `16AngelsBodyDA.png`). Самые большие
текстуры в игре — 1024×512.

### Шрифт (запись типа 0x0C)

Растровые шрифты лежат в `*_FONTSARCHIVE.ARC` и `GLOBALMENUASSETS*.ARC`. Всего их 78 в `Data` и `lData`, и устроены
все одинаково:

```
u16 glyphCount, u16 lineHeight, u16 1, u16 0xFFFF
glyph[glyphCount] по 28 байт: u32 0, u32 width (px), f32 u0, f32 u1, f32 v0, f32 v1, u32 0   (UV в атласе)
u8  advance[glyphCount][glyphCount]   сдвиг пера в пикселях: строка — текущий глиф, столбец — следующий
u8  charMap[256]                      код байта -> номер глифа; 0xFE = пробел, 0xFF = нет глифа
texture                               обычный заголовок текстуры + данные: атлас глифов (в игре DXT3)
```
В каждой строке матрицы есть одно типичное значение (сдвиг глифа) и исключения для отдельных пар (кернинг).
Глиф 0 (код 0x01) — прямоугольник, который рисуется вместо отсутствующих символов. Коды символов — это
8-битные байты текстовых таблиц (Windows-1252), поэтому глифу другого алфавита можно назначить любой свободный
код от 0x80 до 0xFF.

## .LDA — таблица строк

```
char[4] 'lda0' (cp1252) | 'lda1' (UTF-16LE)
u32 fileSize, u32 id0, u32 id1, u32 count
u32 offsets[count], u32 stringsSize
строки, каждая завершается NUL
```
`TEXTxxyy.LDA`: `xx` — язык (00 английский, 01 французский, 02 немецкий, 03 итальянский, …), `yy` — таблица.

## .HDR + .RAW — звуковые банки (`snda`)

```
char[4] 'snda', f32 version (1.0), u32 count, 20 байт резерв
item[count] по 64 байта:
  char name[16], u16 (0x6400), u16 channels, u32 sampleRate, u32 dataStart, u32 0, u32 dataSize,
  u16, u16, u32, f32, u16, ...
```
Данные в `.RAW` — 16-битный PCM со знаком, обычно моно 22050 Гц, записи лежат подряд. У нескольких банков
`ZONE*` записей 0, а их `.RAW` хранит числа с плавающей точкой (параметры), а не звук.
`MUSICARC`/`IGMUSICARC`/`RESULTSMUSIC` — индексы музыки `.OGG`, у них нет `.RAW`.

## .HDR + .SPD — речь комментатора (`spea`)

```
char[4] 'spea', f32 version, u32 phraseCount, u32 streamCount, 16 байт резерв
item[phraseCount] по 36 байт: char name[16], f32, u32, u32, u32 sampleRate, u32 firstStream
stream[streamCount] по 16 байт: u32 start (смещение в .SPD), f32 duration (секунды), u32 0, u32 0
u32 end[streamCount]   // смещение последнего байта каждого потока (включительно)
```
`.SPD` — это подряд склеенные потоки Ogg Vorbis, каждый начинается со страницы BOS. Фраза владеет потоками от
своего `firstStream` до `firstStream` следующей фразы: это несколько дублей одной реплики.
`duration` = granule position последней страницы Ogg / частота дискретизации, ровно как считали оригинальные утилиты.

## Прочее

* `.OGG` — музыка (Ogg Vorbis), заменяется напрямую.
* `.FX` / `.FXC` / `.FXH` — шейдеры HLSL: исходник и скомпилированная версия.
* `.WMV` — ролики, копии файлов из папки `videos\`.
* `.TGA` в архиве — две маленькие маски.
